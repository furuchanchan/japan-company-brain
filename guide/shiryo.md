# 今ある資料を入れる

会社に今ある Word・PDF・Excel・PowerPoint・テキストを、`docs/` の下に置いて `./brain sync` を実行すると、探せるようになります。

```
docs/zensha/kitei/就業規則.docx
docs/zensha/kitei/出張旅費規程.pdf
docs/eigyo/mitsumori/見積の一覧.xlsx
```

```bash
./brain sync
```

## しくみ

エンジン（gbrain）が取り込むのは Markdown だけです。`./brain sync` は取り込みの前に、サーバーの中で資料を Markdown の写しに変えます。

- 写しは元のファイルの隣に `元の名前.md` で置きます（`就業規則.docx` → `就業規則.docx.md`）。元のファイルは変えません
- 元のファイルを直すと、次の `./brain sync` で写しを作り直します
- 元のファイルを消すと、次の `./brain sync` で写しを消し、ページを検索から外します。元のファイルを戻して `./brain sync` を実行すれば、また入ります。Markdown のファイルを消した時も、ページを外します
- ファイル名（拡張子を除いた部分）がページの題になります。日本語のファイル名のままで使えます
- 変換は外へ何も送りません。ネットワークを切った入れ物の中で、4つの形式の変換が通ることを確かめました（2026-11-19）

変換の部品は [markitdown](https://github.com/microsoft/markitdown)（MIT License）です。日本の会社の資料で当たらなくなる所を、4つ直してあります。

| 起きること | 直し |
|---|---|
| PDF から取り出した字に、見た目は同じで別の字（部首の字）が混ざる。「⼿順書」は「手順書」で探しても当たらない | 部首の字を、ふつうの漢字に直す |
| PDF は見た目の行の終わりで改行が入り、語が2行に割れる（「行」と「う」） | 日本語の続きの行をつなぐ。見出し・箇条書き・表はつながない |
| 方眼紙のように使った Excel は、ほとんどのマスが空で、本文が `NaN` で埋まる | 空のマス・空の行・空の列を落とす |
| テキストのファイルが Shift_JIS で書いてある | UTF-8 で読めない時は Shift_JIS で読む |

## 当たり方（測った数）

弊社の手元の資料20件（各形式5件）を入れ、資料1件につき問いを5つ、合わせて100個の質問文で探しました（2026-11-19）。

| 形式 | 資料 | 問い | 上位5件に入った | 1位に出た |
|---|---|---|---|---|
| Word | 5件 | 25 | 24 | 16 |
| PDF | 5件 | 25 | 25 | 19 |
| Excel | 5件 | 25 | 24 | 23 |
| PowerPoint | 5件 | 25 | 19 | 13 |
| 計 | 20件 | 100 | 92 | 71 |

- 問いは資料を PDF に描き出した物を別の AI に読ませ、「社員が自分の AI に聞きそうな質問文」として作りました。変換した Markdown は見せていません
- 変換の部品をそのまま使った時は、上位5件に入ったのは91、1位は69でした。PDF 5件のうち3件に、部首の字が合わせて313字入っていました
- PowerPoint の外れ6問のうち5問は、スライドが画像だけの資料1件です（この資料は「文字が入っていない」として取り込みません）。残りの4件では20問のうち19問が当たりました
- 図や画像の中の文字からしか答えられない問いは10個で、当たったのは7個でした
- 全部で36ページの中で探した値です。資料が多い会社では、この数より下がります。意味で探す検索（埋め込み）は使っていません

## 入らない物

`./brain sync` は入れられなかったファイルと理由を1行ずつ出します。

- スキャンした PDF、画像だけのスライド（文字にする部品が別に要ります）
- 図や画像の中の文字
- 古い形式（.doc・.xls・.ppt）。Word・Excel・PowerPoint で新しい形式に保存し直してください
- パスワードのかかった資料
- 変えた後が200万字をこえる資料（何万行もある Excel など）

## 置く時の注意

- 写し（`.docx.md` など）は `docs/` の中にできます。共有フォルダをそのままつなぐ時は、写しがそこに増えることを先に伝えてください
- 写しを手で直しても、元のファイルを直した時に作り直されます。直す時は元のファイルを直してください
- 読める範囲は置いたフォルダで決まります（Markdown と同じです）
