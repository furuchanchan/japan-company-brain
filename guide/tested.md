# 確かめた範囲と、まだの所

手元の Docker と見本の会社で、次の16個を確かめました（2026-11-19〜20）。`sh tools/selftest.sh` で、同じ確かめをまっさらな写しで回せます（8・15・16個目は手で確かめました）。

1. まっさらな所から `./brain up` と `./brain demo` が通り、権限の43か所が決めた形どおり
2. 同じ質問文の検索が人によって変わる（営業の2人には2件、人事には0件）。営業の人の鍵で書き足したページは、営業と役員には返り、人事には返らない。社外の鍵では書けない
3. `./brain check` を続けて回しても通る
4. 表を HTML に、記録を CSV に書き出せる
5. バックアップから、まっさらな所に復元できる。復元の後も43か所が同じで、AI からも書き込める
6. 復元の後も、渡してあった AI の鍵が使える
7. メンバーを止めると、その人の鍵は次の呼び出しから使えない
8. 実物の Claude Code（2.1.328）からつないで同じ質問をすると、営業の佐藤さんの鍵では見積のページから答えが返り、人事の鈴木さんの鍵では「見つからない」と返る

9. Word と PDF の資料（日本語のファイル名）を取り込んで探せる。PDF の部首の字と行の折り返しが直る
10. Shift_JIS のテキストを取り込める。社内の略語（営推）を、正式な名前（営業推進部）で探せる
11. 和暦の残りの形（R8.10.1・令和八年十月一日）もそろう。問いの側と資料の側が、例の12行で同じ形になる
12. 元の資料を消すと、写しとページも消える
13. 兼務の人は、主の部門と兼ねる部門の両方を読める（50か所が決めた形どおり）
14. つないだ AI への案内の先頭に、記録の書き方の決まりが届く。実物の Claude Code（2.1.328）が、その決まりを読めている

15. メンバーを自分1人にした形（`sample/hitori.json`）で、置き場と鍵を作り、書いた記録を日本語の質問文で探せる（2026-11-20、手で確かめました）

16. 実物の Claude Code（2.1.329、利用者の指示書なし）に「残して」と言わずに決まった事を話すと、記憶に記録が残る（20回中19回。決まりに A・B を足す前は1回中0回、好みと済んだ事を書き足す前は20回中16回）。残らなかった1回は、検収が終わった日を伝えた時。残った19件のうち16件は、後から質問の文で探すと見つかる。書き方の好みとして remember で残った3件は、`./brain search` では見つからない（まだの所）。雑談・計算・言葉の意味の質問5回では何も書かない（5回中0回）。別の新しい会話で聞くと、AI が自分から探して答える（1回中1回）（2026-11-21。20回と5回は、空のフォルダから `claude -p` を1回ずつ動かして数えました）

資料の当たり方（形式ごとの数）は [今ある資料を入れる](shiryo.md) に、記録の書き方の決まりの効き方は [書き方の決まり](../kit/kakikata/README.md) にあります。

次の5つは、まだ確かめていないか、用意していません。

- スキャンした PDF と、図や画像の中の文字（取り込みません）。資料が数千件をこえる会社での当たり方

- 意味で探す検索（埋め込み）。この一式は言葉で探す検索だけを有効にして立てます。エンジンの側の設定で足せますが、この一式では確かめていません
- Claude Code のほかの AI（ChatGPT・Gemini・Cursor・DeepSeek など）からつないだ時の動き
- 会話の全文をそのまま取り込むこと（残すかどうかは AI が会話の中で判断します）。溜まった記録を AI が後から整理し直す動き
- 2台以上のホスト、100人をこえる会社、実際のドメインと証明書で別の PC からつなぐ構成（HTTPS の中継を手前に置く形は、試し用の証明書で確かめました。[サーバーに置く](server.md) に、確かめた所とまだの所を分けて書いてあります）


日本語検索と権限の測り方は [日本語検索の直し](../kit/nihongo-kensaku/README.md) と [権限のひな形](../kit/kengen-4dan/README.md) にあります。
